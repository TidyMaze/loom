1 · What changed?

Two changes deployed together:

  • Retune existing weights (sigma, hl, recH, transHL, sessMs, transSmooth, wC, wR, wT) on the latest 1000-event log via Optuna two-phase search.
  • Add 4 phase-1 context features to the linear blend: audioActive, audioDevice, charging, secsSinceResume. Each adds a decay-weighted, add-k smoothed conditional probability P(ctx | app).
Phase-1 features have only been collected for the last 397 events (40% of log). When ctx is unavailable (first ~600 events), those terms drop out cleanly — old data still trains context/recency/transition normally.

5 · Does it allow better learning?

The model learns better in three distinct ways:

  1. More data per parameter. Retune on 1000 events (vs prior 787) reduces overfitting risk — measured gain is real (+1.4pp from retune alone).
  2. New independent signals. MI of phase-1 features (audioDevice 3.3%, srBin 4.2%, audioActive 2.8%) overlaps only partially with existing features, so adding them as separate linear terms (rather than multiplying into context) yields net gain (+1.3pp).
  3. Tighter inductive bias. PHASE1_SMOOTH=0.63 (add-k Laplace) prevents overconfidence on per-app conditionals with few samples — apps with little ctx history fall back to ~uniform.
What's limiting further gains?
• Only 397 events have phase-1 ctx — ~40% of log. As all 1000 events accumulate ctx, expect lift to grow.
• Charging signal too sparse (27/397) — won't matter until log spans 30+ days.
• Cap raised to 5000 events → next retune will have ~5x richer Markov chain.
• No frequency feature is currently used (wF=0). Solo @1 of frequency alone was 12% — could revisit with longer history.

6 · Method notes

  • Walk-forward CV: warmup=50 then predict event i from events [0..i). No leakage.
  • Optuna search: 200 random (pure exploration) → 400 TPE seeded with phase-1 trials. Best found at trial #596 of 600.
  • Conservative phase-1 eval: simulator uses the most-recent prior event's ctx as proxy for "current ctx" (we don't know real ctx at predict time in a replay). Production calls LaunchContext.capture() with the live state, so phase-1 likely contributes more in production than in this offline measurement.
