What's new in v2 (this iteration)

Error analysis first. Looked at all 713 misses. Top failure: self-loop overprediction — model picks "Chrome" 42 times when user just came from Chrome but actually went to WhatsApp/Messenger/Slack. 99/732 same-app pairs (13.5%) in data — the model overweights "stay on same app" because of recency × transition compounding.
Hypothesis testing. 5 targeted experiments on top of v1:
  • ✓ deployed 2-gram transitions P(C | A→B) using last 2 apps in session (567 triplets in data) — +0.43pp @1, +0.51% MRR
  • ✓ deployed self-loop penalty small subtraction from last-launched pkg when in-session — +0.11pp @1
  • ✗ rejected hour-conditioned transitions — overfits with too few hour-binned pairs (–0.65pp)
  • ✗ rejected log-frequency feature — marginal (+0.15% only at one weight)
  • ✗ rejected fractional-hour Gaussian — high MI in offline binning was an artifact; actual predictions degrade across all (w,σ) tested (−0.16% to −4.30%)
Optuna retune. 250 random + 400 TPE trials with new knobs in search space. Best at trial #483. All 9 existing weights re-converged, picking new equilibrium with 2-gram weight ≈ 1.8 and self-penalty ≈ 0.17.

What we learned:
• The big-three (context, recency, transition-1g) are still the load-bearing signals at 5-6% MRR each.
• 2-gram transition is the next tier (+1.32% MRR) — captures "A→B→C" routines distinct from "A→B" or "B→C" alone.
• audioActive + audioDevice together = ~2.3% MRR — phase-1 features grew in relative importance after retune (BT/speaker is a strong split).
• self-loop penalty contributes little on offline replay (+0.23%) but targets a specific failure mode (Chrome→Chrome overpred). In production with more session continuations it may save more.

What was tested and didn't help

Hour-conditioned transitions P(B|A, hourBin) — sparse data per (A, hourBin) combo. Net –0.65pp @1.
Log-frequency log(1+count[pkg]) — redundant with recency × decay. Best weight = 0.7 gave +0.15% MRR only.
Fractional-hour Gaussian — offline MI of (hour, halfHour) was 40% higher than (hour) alone, BUT all tested (weight, sigma) configs degraded actual prediction by 0.16% to 4.30% MRR. Lesson: MI gain from finer binning is partly mechanical (more cells → less mixing); only real-eval matters.
3-way combo (selfPenalty + 2-gram + hourTrans) — hourTrans dragged net result down (-0.33pp).

Error analysis — where v2 still fails

Top-2 oracle gives 35.65% @1 — there's still +12.7pp available just from better re-ranking of top 2. Future work:

  • Per-app recency curves (Chrome refreshes fast, Calendar doesn't)
  • Burst detection — group consecutive Chrome refreshes as one "logical" launch
  • Notification-aware boost (badged apps move up)
  • App2vec embeddings from co-occurrence — find latent clusters (work apps, social, media)
  • More data → 5000-event cap should unlock richer 2-gram and 3-gram chains

Method notes

  • Walk-forward CV: warmup=50 then predict event i from events [0..i). No leakage.
  • Optuna v2 search: 250 random + 400 TPE (650 trials). Best found at trial #483.
  • Conservative phase-1 eval: simulator uses most-recent prior event's ctx as proxy for "current ctx" (we don't replay live LaunchContext.capture). Production calls capture() with live state, so phase-1 likely contributes more in production than measured here.
  • Scientific discipline: only deployed features that beat baseline on offline eval. Rejected 3 ideas that looked promising on paper (fractional-hour, hour-conditioned trans, log-freq).
